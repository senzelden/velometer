# velometer M16 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** velometer and the Zählwerk Berlin Datalab page served from our own Hetzner server behind a
password, with self-hosted vector tiles, log-based statistics with masked IPs, and a written legal
review whose repo-side fixes are made.

**Architecture:** The velometer export stays a static site. Tiles become one PMTiles file served
beside it (`/tiles/velometer.pmtiles`, outside the export). The Datalab site is a second small
static site built by the CLI from `sites/datalab/` plus a finished velometer export. One checked-in
`deploy/Caddyfile` and `deploy/cloud-init.yaml` define the server; `tools/server.py` creates it
through the Hetzner API, deploys releases with rsync and a symlink switch, and pulls GoAccess
reports.

**Tech Stack:** Python 3.12 (uv, Typer, httpx, pytest), Leaflet 1.9.4 + vendored protomaps-leaflet,
`pmtiles` CLI (pinned binary), Caddy ≥ 2.11.4, GoAccess, cloud-init on Debian 13, rsync over SSH.

**Spec:** `docs/superpowers/specs/2026-10-21-velometer-m16-design.md` (approved 2026-10-21).

## Global Constraints

- Gate: `uv run ruff format --check . && uv run ruff check . && uv run pytest && node --test "src/velometer/app/static/js/tests/*.test.mjs"`; network tests `@pytest.mark.slow`.
- `velometer.sqlite` is never written (md5 before and after).
- Domain parameter everywhere; the intended value is `zaehlwerk-datalab.de`, apex = Datalab, `velometer.<domain>` = velometer, `www.<domain>` redirects to the apex.
- No page loads anything from a host other than its own (CSP, export scan, render-pass audit).
- Caddy exact version ≥ 2.11.4 (2.10.2 answers `.gz` with 206). Every pinned binary or vendored file: exact version at least two weeks old, with a checksum or a `VERSIONS` line.
- No npm dependency in the repo; no new runtime Python dependency.
- Secrets only via direnv + pass: `HCLOUD_TOKEN` ← `velometer/hcloud-token`, `VELOMETER_PREVIEW_PASSWORD` ← `velometer/preview-password`. No raw value, no bcrypt hash and no private key in any repo file.
- Never `rm -rf`; deleting old releases only with a guard that the path lies under `releases/`.
- Outward-facing steps (create/resize/delete a server, DNS, deploy, go-live, push) only after the user's explicit go, each time.
- Access logs: client IP masked to IPv4 /24 and IPv6 /48 before it reaches disk; Cookie and Authorization dropped; daily roll, kept 14 days.
- Reader-facing wording: "mapped km", never "built km" (ADR 0006). A reworded sentence ships only after the user reviewed it.
- Commits end with `Assisted-by: Claude:claude-opus-5-5`; stage explicit paths.

## Review Focus

1. A visitor without the password (and a search crawler) gets `401` on every path of both hosts, including `/tiles/…`, the 404 page and `www.` — nothing leaks. Test in Task 7.
2. A map page whose tile file is missing or unreachable still shows the tier lines and no console error. Test in Task 5.
3. An interrupted deploy (rsync fails halfway) leaves `current` on the previous complete release. Test in Task 8.
4. Caddy's error log and default logger never write an unmasked client IP (an error request, e.g. a malformed Range on `.pmtiles`). Test in Task 7.
5. A dark-theme reader gets a dark basemap without the old CSS invert filter on vector tiles (no double inversion). Test in Task 5 (render-pass screenshot plus a CSS test that the filter rules are gone).

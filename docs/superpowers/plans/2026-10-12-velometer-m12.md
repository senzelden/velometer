# velometer M12 German edition: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a complete German edition of the reader app under `/de/`, with the same pages,
the same depth and the same guarantees as the English one. Every number in German prose is
checked against the data, and German text that has fallen behind its English source is reported
stale.

**Architecture:**
- **`velometer/i18n.py`** is the one place for languages:
  - the UI catalogue (`content/ui/en.yaml`, `content/ui/de.yaml`) and `t()`;
  - number, sign, percent, month and date formatting, and the only copy of the month names;
  - the German-content completeness gate (`GERMAN_CONTENT_REQUIRED`, which applies to the shipped
    content tree only).
- **Routing.**
  - Every page route is registered twice, at `""` and `"/de"`. Each registration binds its
    language, and the route sets `request.state.lang` from it; the path is never sliced.
  - `u()` adds `de/` to page links after the base path. Data, map and static URLs go through
    `data_u()`, which never adds a language except for the one per-language data file,
    `search.json`.
  - Each language has its own Jinja environment, with `t`, `u` and the formatting filters bound
    to it.
- **German prose** lives in translation files beside the English ones.
  - A translation file holds only the translatable text, in the English file's structure, and
    every string is stamped with a hash of its English source.
  - Facts, quotes, roles, steps and ids come only from the English file. Data references keep
    their structure (id, file, locator, route) in the English file only. Their label is visible
    link text, so the translation file holds a German label per data-ref id (a pre-flight
    ruling, which refines spec §4.4's "data references are shared").
- **Rendering.** A loader merges each translation over its English model, and the existing
  renderers draw it. A missing German string falls back to English inside
  `lang="en" data-fallback`.
- **`content --check`** runs the existing English check, unchanged, then a German one: German
  numbers, German rule families, marker parity, completeness and staleness. German problems are
  printed with a `[de] ` prefix.
- **Data stays shared.** CSV, `series.json` and the English PNG are shared by both editions.
  - `series.json` gains only additive `_de` fields, and a JS `localised(series, lang)` applies
    them on German pages.
  - `/de/data/search.json` and `{name}.de.png` are the two per-language files.

**Tech Stack:** FastAPI/Jinja2, Pydantic v2, PyYAML, Typer, plain ES modules tested with
`node --test`, pytest, `tools/render_pass.py` (headless Chrome + axe-core 4.13.0). No new
dependency.

**Spec:** `docs/superpowers/specs/2026-10-12-velometer-m12-design.md` (amended: `presets.yaml`
gets no `basis_de`).

## Notes on the decomposition

The plan keeps the eleven proposed tasks. These boundaries moved because the code required it:

1. **The glossary is Task 3's first step.** Task 3 drafts the bulk of the German UI strings, which
   must use the fixed terms (spec §4.10). Tasks 1 and 2 add only a handful of German values:
   `fmt.na`, the language switch, the 404 and the footer.
2. **The server-HTML leak test lands in Task 3**, where the English literals leave the
   templates, with a catalogue source (enforced) and a content source (skipped through
   `LEAK_EXCLUDED` until Task 7 tags English fallback). Task 5 adds and enforces a config
   source. Task 11 adds the Chrome step for JS-drawn text.
3. **`ReportData.lang` / `with_lang()` lands in Task 2.** Every page handler receives
   `ReportData` through one dependency (`report_data()`, `main.py:384`), so language plumbing
   belongs with the routes.
4. **`presets.yaml` gets no `basis_de`** (spec amended). Its bytes feed `config_sha256`
   (`selection.py:61`), and its `basis` values are ids.
5. **All `series.json` `_de` fields land in Task 7**, together with the JS that applies them.
6. **`tools/review_rows.py` is built in Task 9**, so Task 10 runs no implementer code.

## Pre-flight rulings

These are the controller's rulings on the pre-flight scan
(`.superpowers/sdd/2026-10-12-velometer-m12/preflight.md`), applied throughout:

**Gate and CLI:**
- Ruling: the gate stays green at the end of every task. — Red is never handed to the next
  task. — Cost: some tests move between tasks.
- Ruling: `content --check` prints English problems exactly as today and German problems with a
  `[de] ` prefix. While the gate is off, German completeness notes are returned but not printed,
  and `--online` is gated only on problems, never on notes. — The existing exact-output tests
  (`test_content_m8.py:602/604`, `test_content_check.py:327`) stay unchanged. — Cost: notes are
  visible only through the API.
- Ruling: there is no process-wide switch.
  - `require_de` is an explicit check parameter. It defaults to
    `i18n.german_required(content_dir)`, which is `GERMAN_CONTENT_REQUIRED` for the shipped tree
    and False for any other tree.
  - The `gloss_de` rule lives in the check, not in a Pydantic validator.
  - — Synthetic `Source`s and hand-built trees in existing tests stay valid after Task 9 flips
    the constant. — Cost: the gate is a path comparison.

**Leak and sniff tests:**
- Ruling: Task 5's function-word sniff covers only config-derived text, scoped through
  `config.reader_prose()` (the `_de` values themselves). — Prose stays out until Tasks 7–8. —
  Cost: the sniff does not look at pages; the config phrase source of the leak test does.

**Routes and pages:**
- Ruling: fragments (`/city/{id}/panel`) carry `lang` on their root element, and the twin test
  checks `<html lang>` for full pages and the root `lang` for fragments. — A fragment has no
  `<html>`. — Cost: one attribute in the English panel, listed in the English diff.
- Ruling: the footer is catalogued in Task 2. — `/methodology/de` gets German chrome in Task 2,
  and its footer links must stay German. — Cost: Task 2 drafts a few German strings before the
  glossary; Task 3 reviews them against it.
- Ruling: the language comes from route registration, never from slicing the path. — A slice
  with `base_path` breaks every `/velometer/` export. — Cost: a small registration helper.
- Ruling: the 404 handler takes its language from a `/de` path prefix, else `en`, renders both
  language blocks anyway, and supplies `here="/"`. — No route ran for a 404. — Cost: none.
- Ruling: `strip_lang("/methodology/de")` is `/methodology`. — Its alternates must resolve. —
  Cost: none.
- Ruling: every Python-built page href (`main.py:866,882` and others) goes through the
  language-aware helper, and a test scans `/de/` pages for links to English twins. — A German
  page must not lead back to English except through the switch. — Cost: none.

**JS, formats and downloads:**
- Ruling: `localised(series, lang)` lives in `static/js/data.js`, has node tests, and is used by
  compare, the city charts and downloads. It lands in Task 7, which owns all `series.json`
  `_de` fields. — A shared static file needs a client-side swap. — Cost: German names in
  JS-drawn charts wait until Task 7.
- Ruling: `fmt.parse` is part of `fmt.js`, `tableCsv` takes the locale explicitly, and `slug`
  maps ß to "ss". — These are missing interfaces. — Cost: none.
- Ruling: the image source line ("OSM mapped km, not built km") has a German catalogue form.
  Only the CSV preamble stays English. — Spec §4.5. — Cost: none.
- Ruling: `tableCsv` never changes English CSV output, and rewrites number cells to dot
  decimals only when the locale is `de`. `download.test.mjs:105` stays as it is. — The English
  edition is unchanged. — Cost: none.
- Ruling: the Python↔JS "same key" mirror test is dropped. Separate tests check that the Python
  counter keys exist in the catalogue and that the JS keys exist. — Python and JS keys live in
  different families. — Cost: none.

**Content check and names:**
- Ruling: `check_content_all` takes `history`, and the staleness tests pass it explicitly. —
  Test trees are not git repositories. — Cost: none.
- Ruling: `load_cities(path)` is the real signature (`config.py:329`). — Cost: none.
- Ruling: the country key family is sourced from the countries of `config/cities.yaml`, because
  the names themselves move into the catalogue. — `names.COUNTRY_NAMES` is removed. — Cost:
  none.

**Tests and fixtures:**
- Ruling: the exonym snapshot test, `tests/city_names.json` and `tests/ui_js_strings.json` are
  accepted. — The first is the spec's list; node cannot read YAML without npm; tests keep the
  JSON fixtures equal to their sources. — Cost: fixtures to regenerate.
- Ruling: there is one shared `make_source` factory and one app builder (`app_for`) in
  `tests/conftest.py`. German month names come only from `i18n`, and the JS fixture is generated
  from it. — No duplicated helpers or data. — Cost: none.
- Ruling: `DYNAMIC_FAMILIES` declares every id-built key family, each sourced from its live

  - Tables hold ids, not keys, and a test asserts that every composed key prefix in the code is
    a declared family.
  - Month names are not catalogue keys at all: `js_strings` injects them from `i18n`.
  - — The "every defined key is used" test is neither red nor leaky. — Cost: a code-scanning
    test.

**Constraints:**
- Ruling: data-ref labels are translated strings in the translation file, and the data-ref
  structure stays shared. — They are visible link text. — Cost: a refinement of spec §4.4.
- Ruling: page URLs go through `u()` and data URLs through `data_u()`. The search meta uses

- Ruling: the construction-verb constraint states the rule actually checked (see Global
  Constraints). — Cost: none.

Project rules that also bind every task:

- **The gate is green at the end of every task.**
- **Construction verbs.** German content prose, outside quotes, uses none of the
  construction-verb forms the content check flags: `gebaut`, `baute`, `bauten`, `errichtet`,
  `eröffnet`, `entfernt`, `zurückgebaut`. These are the twins of English
  built/constructed/opened/removed. The UI and map strings say "kartierte km, nicht gebaute km",
  which the check does not scan.
- **ODbL attribution in every download and citation.** In English: "Map data © OpenStreetMap
  contributors, ODbL 1.0". In German: "Kartendaten © OpenStreetMap-Mitwirkende, ODbL 1.0".
- **The M10 rules hold:**
  - colours only as tokens;
  - 4.5:1 text and 3:1 non-text contrast;
  - `table.stack` with `data-label`;
  - a visible `:focus-visible` ring;
  - zero axe violations;
  - announcements through `live.js` `announce(text)`.
- **Internal URLs.**
  - Page URLs in templates and Python go through `u()`, which is language-bound. Data, map and
    static URLs go through `data_u()`.
  - Every URL in JS goes through `url()` (`static/js/base.js`).
  - Scripts are `type="module"` files under `/static`, and JSON goes in
    `<script type="application/json">`.
- **Classifier and config files.**
  - Classifier rules are data (`config/classifier/vN.yaml`). M12 changes no rule.
  - `config/presets.yaml`, `config/activity.yaml` and the classifier files are not edited. Their
    bytes are run identity.
- **No displayed number, run, classifier or DB change.** The English edition changes only in the
  categories Task 11 Step 5 lists.
- **Git.** Stage explicit paths, never `git add -A`. Do not change git config. Do not write the
  maintainer's Gmail address anywhere; the git identity is the posteo one.
- **Secrets:** never write a raw value into any file.
- Ruff line length is 100.

    r"""\bt(?:_in|_markup)?\(\s*(?:(?:['"](?:en|de)['"]|lang)\s*,\s*)?"""
    r"""(?:f['"]([a-z][\w.]*\.)\{|['"]([a-z][\w.]*\.)['"]\s*~|`([a-z][\w.]*\.)\$\{)"""

class _Text(HTMLParser):
    def __init__(self):
        super().__init__()
        self.found, self.skip = [], 0

    def handle_starttag(self, tag, attrs):
        self.skip += tag in {"script", "style", "code", "pre"}
        self.found += [v for k, v in attrs if k in ATTRS and v]

    def handle_endtag(self, tag):
        self.skip -= tag in {"script", "style", "code", "pre"}

    def handle_data(self, data):
        if not self.skip:
            self.found.append(data)


def _words(text):
    return [w for w in re.findall(r"[^\W\d_][\w'’+-]*", text.replace("\x00", " "))
            if w not in ALLOWED]  # fmt: skip


def _read(paths):
    return {p: p.read_text(encoding="utf-8") for p in paths}


def test_no_template_has_literal_text():
    bad = []
    for path, text in _read(HTML).items():
        p = _Text()
        p.feed(JINJA.sub("\x00", text))
        bad += [f"{path.name}: {s.strip()!r}" for s in p.found if _words(s)]
    assert bad == []


def test_no_jinja_string_literal_of_two_or_more_words():

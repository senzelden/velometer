# velometer M12 German edition: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve a complete German edition of the reader app under `/de/`, with the same pages,
the same depth and the same guarantees as the English one. Every number in German prose is
checked against the data, and German text that has fallen behind its English source is reported
stale.

**Architecture:**
- **`velometer/i18n.py`** is the one place for languages:
  - the UI catalogue (`content/ui/en.yaml`, `content/ui/de.yaml`) and `t()`;
  - number, sign, percent, month and date formatting;
  - the German-content completeness gate.
- **Routing.** Every page route is registered twice, at `""` and `"/de"`, and `request.state.lang`
  carries the language. `u()` adds `de/` to page links after the base path and never to data
  links. Each language has its own Jinja environment, with `t`, `u` and the formatting filters
  bound to it.
- **German prose** lives in translation files beside the English ones. They hold only the text,
  in the English file's structure, and every string is stamped with a hash of its English source.
  Facts, data references, quotes, roles and ids come only from the English file.
- **Rendering.** A loader merges each translation over its English model, and the existing
  renderers draw it. A missing German string falls back to English inside `lang="en"`.
- **`content --check`** runs the existing English check, then a German one: German numbers, German
  rule families, marker parity, completeness and staleness.
- **Data stays shared.** CSV, `series.json` and the English PNG are shared by both editions.
  `series.json` gains only additive `_de` fields. `/de/data/search.json` and `{name}.de.png` are
  the two per-language files.

**Tech Stack:** FastAPI/Jinja2, Pydantic v2, PyYAML, Typer, plain ES modules tested with
`node --test`, pytest, `tools/render_pass.py` (headless Chrome + axe-core 4.13.0). No new
dependency.

**Spec:** `docs/superpowers/specs/2026-10-12-velometer-m12-design.md`

## Notes on the decomposition

The plan keeps the eleven proposed tasks. Four boundaries moved because the code required it:

1. **The glossary is Task 3's first step**, not part of a drafting task. Task 3 drafts the German
   UI strings, which are the first German text written, and they must already use the fixed
   terms (spec §4.10).
2. **The server-HTML leak test lands in Task 3**, where the English literals leave the
   templates. It is not deferred to Task 11, because Tasks 4, 5, 7 and 9 each remove English
   from `/de/` pages and need a red test.
   - The test starts with a named exclusion list (`LEAK_EXCLUDED`). Each later task removes its
     own entries, and Task 9 empties the list.
   - Task 11 adds the Chrome step for JS-drawn text.
3. **`ReportData.lang` / `with_lang()` lands in Task 2.**
   - City names, preset labels and the headline unit are produced by `ReportData`, and every
     page handler receives it through one dependency (`report_data()`, `main.py:384`).
   - Language plumbing therefore belongs with the routes. Task 3 uses it for units, and Task 5
     uses it for `name_de` and `label_de`.
4. **`presets.yaml` gets no `basis_de`. This deviates from spec §4.3 and is flagged for the
   controller.**
   - The file's bytes feed `config_sha256` (`selection.py:61`, `run.config_sha256(classifier,
     presets.yaml, activity.yaml)`), so editing it orphans every stored run.
   - Its `basis` values are machine ids (`per_side`, `qecio_weighted`, `{parameter: …}`) with no
     prose. The reader-visible basis words already come from `differences.yaml`
     (`length_bases`, `bases`), and those get `_de` siblings in Task 5.

The review stop (Task 10) needs a rows file. `tools/review_rows.py` is built and tested in
Task 9, so Task 10 runs no implementer code.

## Review Focus

These are the five input classes most likely to hurt a reader, each pinned by a test in its owning
task:

1. **A German permalink with a query or hash.**
   - Case: `/velometer/de/compare?cities=berlin,vienna&metric=…#…` under a base path, then
     "English" clicked, or a link followed inside `/de/`.
   - Expected: the switch keeps the query and hash and drops only `de/`. Every page link inside a
     German page stays under `/velometer/de/`. Data links never gain `de/`.
   - Pinned in Task 2: `url_cases.json` `emit_lang` cases (shared by pytest and node), the
     `switchHref` node cases, and an app test over every `/de/` page's `href`s.
2. **The `lang="en"` fallback inside a German page.**
   - Expected: a missing German paragraph, heading, gloss or explanation renders in English
     inside an element with `lang="en"` and `data-fallback`. The page still answers 200, never
     shows a raw key, and logs once.
   - Proof fails on any `data-fallback` once the gate is on.
   - Pinned in Task 7 (render tests with one string removed from a fixture translation) and
     Task 9 (no `data-fallback` on any `/de/` page).
3. **German city names in downloads, file names and citations.**
   - Case: "Kraków" / "Krakau" / "Warszawa" / "Warschau" in a German chart download.
   - Expected: the title, source line and citation title say "Krakau". The file name slug folds
     to `krakau`, and ß folds to `ss`. The CSV header is German, but its number cells keep dot
     decimals. Search finds "Krakow", "Kraków" and "Krakau" in both editions.
   - Pinned in Task 4 (node `fileName` and citation cases) and Task 5 (`name_de` on every page
     kind) and Task 7 (search terms).
4. **German numbers beside markers and inside citations in the content check.**
   - Case: "78,2 %[#x]", "1.639,8 km", "−3,2", "um 12,3 Prozent [@krakow-250km-2022]", a stray
     English "78.2" in German text, and "am 1. Januar".
   - Expected: digits inside `[#…]`/`[@…]` are never read as numbers. "78,2" is 78.2, not 782.
     An English decimal point in German text is reported. A German ordinal before a month name is
     not a number.
   - Pinned in Task 6's number tests.
5. **A stale stamp after an English edit.**
   - Expected: a whitespace-only change to the English (re-wrapped YAML) is not stale. A
     one-character change is stale and the message shows the old and new English.
     `content stamp` re-stamps only the file it is given.
   - Pinned in Task 6's staleness tests.

import re
from html.parser import HTMLParser
from pathlib import Path

from velometer import i18n

ROOT = Path(__file__).resolve().parents[1]
TEMPLATES = ROOT / "src/velometer/app/templates"
CODE = [*(ROOT / "src/velometer").rglob("*.py"), *TEMPLATES.rglob("*.html"),
        *(ROOT / "src/velometer/app/static").rglob("*.js")]  # fmt: skip
ATTRS = {"aria-label", "title", "alt", "placeholder", "data-label"}
# brand and language-neutral symbols; a word here must read the same in both editions
ALLOWED = {"velometer", "km", "m", "CSV", "PNG", "SVG", "JSON", "BibTeX", "CSL", "LAU", "FUA",
           "OSM", "A", "B", "C", "D", "E", "A+B", "ODbL", "n", "k", "×", "·", "›", "▾", "→", "%"}  # fmt: skip
JINJA = re.compile(r"\{\{.*?\}\}|\{%.*?%\}|\{#.*?#\}", re.S)
KEY_USE = re.compile(r"""\bt(?:_in|_markup)?\(\s*(?:['"](?:en|de)['"]\s*,\s*|lang\s*,\s*)?['"]([a-z][\w.]*)['"]""")  # noqa: E501
# any quoted dotted key, so keys held in tables (TABS, KIND, ...) and passed to t() later count
KEY_LITERAL = re.compile(r"""['"]([a-z][a-z0-9_]*(?:\.[A-Za-z0-9_]+)+)['"]""")


class _Text(HTMLParser):
    def __init__(self):
        super().__init__()
        self.found, self.skip = [], 0

    def handle_starttag(self, tag, attrs):
        self.skip += tag in {"script", "style", "code", "pre"}
        for k, v in attrs:
            if k in ATTRS and v:
                self.found.append(v)

    def handle_endtag(self, tag):
        self.skip -= tag in {"script", "style", "code", "pre"}

    def handle_data(self, data):
        if not self.skip:
            self.found.append(data)


def _letters(text):
    words = re.findall(r"[^\W\d_][\w'’+-]*", text.replace("\x00", " "))
    return [w for w in words if w not in ALLOWED]


def test_no_template_has_literal_text():
    bad = []
    for path in sorted(TEMPLATES.rglob("*.html")):
        p = _Text()
        p.feed(JINJA.sub("\x00", path.read_text(encoding="utf-8")))
        bad += [f"{path.name}: {s.strip()!r}" for s in p.found if _letters(s)]
    assert bad == []

            bad += [f"{path.name}: {m[1]!r}" for m in lit.findall(block) if len(m[1].split()) >= 2]

## Rulings this plan makes (copy into `rulings-m12.md` in Task 11)

**Config and data:**
- Ruling: `presets.yaml` gets no `basis_de`. — Its bytes are run identity (`config_sha256`), and
  its `basis` values are ids; the reader-visible basis words come from `differences.yaml`. —
  Cost: a deviation from spec §4.3's list, flagged to the controller.
- Ruling: `figures.csv` `note_de` is read beside the DB, keyed by the English note text. —
  Notes live in the DB and the DB is never written. — Cost: one extra CSV read per page build,
  cached.
- Ruling: plan titles get `title_de` only where the English title has English words (Vienna,
  Copenhagen). — Spec §4.3 keeps German titles, and two titles are mixed. — Cost: two optional
  fields.
- Ruling: `series.json` carries additive `_de` fields (`name_de`, `country_name_de`,
  `presets_de`, `headline_unit_de`, counter `none_de`) besides `explanations_de`. — The JS draws
  names, units and notes from `series.json`, and data stays shared (spec §4.1). — Cost: a larger
  JSON file.
- Ruling: `ROAD_CLASS_TEXT`, `TIER_LABEL` and `HEADLINE_UNIT` stay as English constants for the
  CLI, and a test keeps them equal to the `en` catalogue. — The CLI outputs are English by spec
  §9. — Cost: one duplicated value set, guarded.
- Ruling: external-figure ids (`network_scope`, `length_basis`) are translated on German pages
  only. — English shows raw ids today, and changing that is outside M12. — Cost: the editions
  differ in form there.
- Ruling: the QECIO and BikeNetKit loader notes stay English inside `lang="en"`. — They are
  generated data notes, not prose; translating them would mean a loader change and a DB
  rewrite. — Cost: a few English lines on German pages, correctly tagged.

**Content check and translations:**
- Ruling: data-ref labels are translated. — They are visible link text. — Cost: one more
  translatable path per data ref.
- Ruling: problem messages are prefixed `[en]` / `[de]` only by `check_content_all`. — Existing
  tests pin the unprefixed strings. — Cost: none.
- Ruling: `content` becomes a Typer group with a callback. — `content stamp` needs a subcommand,
  and `content --check` must keep working. — Cost: help output changes shape.
- Ruling: the completeness gate is `i18n.GERMAN_CONTENT_REQUIRED`, off until Task 9. —
  Machinery lands before the prose (spec §4.10), and the gate must be explicit and tested. —
  Cost: German completeness is a note, not an error, for Tasks 6–8.
- Ruling: the old English in a stale message comes from git history. — The stamp holds only a
  hash. — Cost: a git call per stale string; "(not found in git history)" when the history has
  been rewritten.

**UI strings and formats:**
- Ruling: the catalogue lives at the fixed repo path `content/ui` and is cached by mtime. — The
  CLI (`report maps`) needs it without an app `content_dir`. — Cost: an installed wheel would
  need the path; this is the same as today's `Path("content")` defaults.
- Ruling: node tests read JS strings from the committed `tests/ui_js_strings.json`, which a
  pytest keeps equal to the catalogue. — Node cannot parse YAML without npm. — Cost: one
  regenerated fixture per JS string change.
- Ruling: German chart CSV number cells use the English machine form, while the header is
  German. — Spec §4.5 says machine formats. — Cost: none.
- Ruling: the citation's accessed date stays ISO in German. — It is a machine-checked field
  shared with CSL. — Cost: a mixed-format citation line.
- Ruling: unit and format symbols are allowlisted in the template literal guard. — They read the
  same in both languages. — Cost: an allowlist to keep short.

# velometer M14 (ready to host, plus follow-ups) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the static edition ready to serve from `velometer.<datalab-domain>` on any static
host, without deploying it. Close the M13 follow-ups on accessibility, small fixes and OCR.

**Architecture:** There is no new subsystem. Each task extends one existing area:
- site settings and the footer (`config/site.yaml`, `config.py`, `app/main.py`,
  `templates/base.html`);
- the export (`app/export.py`) and a new `app deploy-check` command (`cli.py`);
- the deploy guide (`docs/deploy.md`);
- UI strings (`i18n.py`, `content/ui/*.yaml`);
- city, plan and source languages (`config/cities.yaml`, models);
- templates (captions, Sources links);
- chart downloads (`static/js/download.js`, `download-ui.js`);
- tests (ResourceWarnings);
- the online check (`content/check.py`, OCR through the Mistral API);
- HANDOVER §12;
- the Orca driver (`tools/orca_pass.py`).

**Tech Stack:** Python 3.14 via `uv`; FastAPI/Starlette and Jinja2; Pydantic v2; Typer; SQLite
(read-only here); vanilla ES modules with `node --test`; headless Chrome over CDP
(`tools/render_pass.py`); Orca 50.2 (`tools/orca_pass.py`); poppler (`pdftotext`, `pdfseparate`,
`pdfunite`, `pdfinfo`); `httpx` for the Mistral OCR API.

**Spec:** `docs/superpowers/specs/2026-10-16-velometer-m14-design.md`. The user approved it on
2026-10-16, together with pre-approval to implement without further check-ins. Read the spec
before your task; its §3 lists the surveyed facts.

## Global Constraints

- Gate: `uv run ruff format --check . && uv run ruff check . && uv run pytest && node --test "src/velometer/app/static/js/tests/*.test.mjs"`.
  The full pytest run takes about 10 minutes. Run targeted tests while iterating and the full
  gate once at the end of each task.
- **Never run `rm -rf`** or any recursive force delete, and never write one into a script or a
  brief. Delete single files with `rm <file>` or `git rm`. Prefer the tools' own `--clean`.
  `shutil.rmtree` calls that already exist in the code stay as they are; add no new ones outside
  tests' `tmp_path`.
- The Bash sandbox cannot start on this machine, so run Bash with `dangerouslyDisableSandbox: true`.
- `/tmp` is at its user quota. Put scratch under `data/scratch-m14/` (git-ignored).
- Commits:
  - stage explicit paths, never `git add -A`;
  - end the message with exactly one trailer, `Assisted-by: Claude:claude-opus-5-5`;
  - never use `Co-Authored-By:`;
  - commit on branch `m14`.
- Nothing is deployed. No server, DNS, Cloudflare or Hetzner step, no upload, no `git push`.
- Secrets: `MISTRAL_API_KEY` comes from direnv (`use_pass_optional MISTRAL_API_KEY api/mistral` in
  the git-ignored `.envrc`, already set up and loaded).
  - Never print, log, write or echo the key, and never put it in a test, fixture, report or commit.
  - Tests never call the Mistral API (spec §4.5). The one real call is the controller's acceptance
    run in Task 12.
- No new Python dependency and no npm. `httpx` and the poppler tools are already present.
- No stored number changes, no DB write, no OSM run. `velometer.sqlite` stays byte-identical.
- No new host the pages load from. Plain `<a href>` links to the Datalab's https pages are not
  loads.
- Every reader-visible English UI string has its German twin in `content/ui/de.yaml`
  (`check_catalogues`). M14 adds no narrative prose, so no `content stamp` is needed.
- Tests assert the rule, not today's value or this machine's state. Each one is shown red first by
  breaking the rule, and the report says how.
- Rulings an implementer makes go into the task report as
  `Ruling: <what> — <why> — <cost if wrong>`. The controller copies them into
  `docs/superpowers/rulings-m14.md`.

## Review Focus

1. **A half-filled `config/site.yaml`.** For example `datalab.name` set but `datalab.url` null, or
   an Impressum URL without a privacy URL. Loading must fail with the field named, rather than
   render half a footer line. An `http://` URL is refused. Task 1 adds the tests.
2. **A `.gz` that no longer matches its file**, for example a file edited by hand after the export.
   `deploy-check` must name it. The export with `--clean` rewrites every `.gz`. Task 3 adds the test.
3. **A UI string with an `<i lang>` mark used where only text is allowed:** an `aria-label`, the
   `#ui-strings` JS block, a CSV header, a citation. It must come out as plain text, with no
   `<i`, no `&lt;i` and no lost word. Task 4 adds the test.
4. **A PDF whose scanned page is not the first**, for example page 3 of 5 with pages 1, 2, 4 and 5
   holding text. Only page 3 is sent, and the OCR text is credited to page 3, also in the cache
   key. Task 9 adds the test.
5. **A downloaded chart title with one word wider than the room.** It stays whole on its own line
   (today's rule), and no line holding several words exceeds the room. Task 7 adds the test.

### Task 2: Export, part 2: `.gz` siblings, the size guard and `_headers`

**Files:**
- Modify: `src/velometer/app/export.py`.
- Test: `tests/test_m14_export.py` (new).

**Interfaces:**
- Produces, in `export.py`:
  - `GZ_TYPES = (".html", ".css", ".js", ".json", ".geojson", ".csv", ".svg")`;
  - `GZ_MIN_BYTES = 1024`;
  - `MAX_FILE_BYTES = 26_214_400` (25 MiB);
  - `HEADERS_FILE = "_headers"`;
  - `write_gz(site: Path) -> int`: the number of `.gz` files written;
  - `headers_text(base: str, csp: str) -> str`;
  - `oversized(site: Path, limit: int = MAX_FILE_BYTES) -> list[str]`: relative paths.

- [ ] **Step 1: Write the failing tests** in `tests/test_m14_export.py`. Use the existing small
  export fixture; find how `tests/test_export.py` builds one, and reuse that helper.
  - **Compressed copies:**
    - every exported file with a suffix in `GZ_TYPES` and at least `GZ_MIN_BYTES` has a sibling
      `<name>.gz` that `gzip.decompress`es to its bytes;
    - no `.gz` exists for smaller files or other types (`.png`);
    - two exports of the same inputs give byte-identical `.gz` files: the mtime is 0 and no file
      name is stored, so the copies are reproducible.
  - **Size guard:** `oversized` on a tmp dir with a file of `limit` bytes reports it, and a file of
    `limit - 1` bytes does not. `_run_export` with `MAX_FILE_BYTES` monkeypatched to a small value
    raises `ExportError` naming the file.
  - **`_headers`:**
    - it exists at the export root;
    - its `Content-Security-Policy` value equals the pages' meta CSP plus `; frame-ancestors 'none'`.
      Read the meta from an exported `index.html`, never from a literal in the test;
    - it carries `X-Content-Type-Options: nosniff`,
      `Referrer-Policy: strict-origin-when-cross-origin` and `Cache-Control: public, max-age=3600`;
    - its path pattern is `<base>*`, so `/*` for base `/` and `/velometer/*` for `/velometer/`.
  - **Reference scan:** `scan_references` passes; `.gz` and `_headers` are not treated as pages.
- [ ] **Step 2: Run them and see them fail.**
- [ ] **Step 3: Implement.**
  - **`.gz` files:** `write_gz` walks the staging site after `_write_site` and before the
    reference scan. For each eligible file it writes the copy with `gzip.GzipFile(filename="",
    mode="wb", compresslevel=9, fileobj=…, mtime=0)`.
  - **`_headers`:** `headers_text` builds the file in the Cloudflare Pages / Netlify format:
    ```
    <base>*
      Content-Security-Policy: <csp>; frame-ancestors 'none'
      X-Content-Type-Options: nosniff
      Referrer-Policy: strict-origin-when-cross-origin
      Cache-Control: public, max-age=3600
    ```
    Take `<csp>` from the same `CSP` constant `main.py` uses for the meta. Import it; don't
    duplicate it.
  - **Size guard:** run `oversized(site)` after writing. Any hit raises `ExportError`, with the
    files listed.
  - **Reference scan:** make it skip `*.gz` and `_headers`, extending its existing file-type
    filter.
  - **Module docstring:** add one line for the three additions.
- [ ] **Step 4: Run the tests and see them pass.** Then red-proof:
  - set `mtime` to the current time and watch the reproducibility test fail;
  - restore it.
- [ ] **Step 5: Run the gate and commit** as `feat(m14): export writes .gz siblings, _headers and

### Task 7: Downloaded titles wrap by measured line width

**Files:**
- Modify: `src/velometer/app/static/js/download.js` and `download-ui.js` (where the measure comes
  from).
- Test: `src/velometer/app/static/js/tests/download.test.mjs`.

**Interfaces:**
- Produces: `wrap(text, measure, room)` and `fit(text, measure, room)`, where
  `measure: (s: string) => number` gives a string's width in px. `layoutKey` and the title layout
  take a `measure`.
  - When the page gives none, `measure` falls back to `s => s.length * CHAR` (or `TITLE_CHAR`
    for titles), which is today's estimate.
  - `download-ui.js` passes a measure that renders the string in an offscreen SVG `<text>` with
    the title's or key's font and reads `getComputedTextLength()`.

- [ ] **Step 1: Write the failing tests** in `download.test.mjs`:
  - **No overrun:** with a stub measure that charges each glyph its own width (`W` and `Ä` 14,
    `i` 4, the rest 8), a title mixing "WWWW ÄÖÜ …" and narrow words wraps so that every line of

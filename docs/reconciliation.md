# Reconciliation: velometer vs published figures

Generated by `velometer reconcile --write` from the latest done LAU run per city and the
external figures in the database (`config/external/figures.csv`, QECIO v2.10, BikeNetKit).
Gap = (ours − theirs) / theirs. Every gap flagged **>20%** needs an explanation below, under a
heading `### <key>`; `velometer reconcile --check` enforces this.

Tags: `boundary_mismatch` (different area than ours), `definition_mismatch` (different
definition of the quantity), `date_gap` (figure and OSM snapshot more than a year apart),
`scope_mismatch` (the figure covers a different network scope than ours, e.g. Vienna's web
correction that adds traffic-calmed roads with restricted motor access; such rows get their own
key `<city>/<comparison>@<scope>`, still flag over 20% and still need an explanation).

Comparison map: `config/reconcile.yaml`. Our numbers are OSM *mapped* km (ADR 0006).

Clean Cities basis: the Clean Cities comparisons (`cc_ratio`, `cc_km`) follow the
`clean_cities_basis` parameter in `config/presets.yaml` (default `per_side`, ADR 0003), or
`--clean-cities-basis` for one command. Both bases are stored for every run, so switching needs
no rerun. A comparison that depends on the parameter also gets an informational row on the
other basis, keyed `<city>/<comparison>~<basis>` (for example `berlin/cc_km~qecio_weighted`);
it is never flagged and never needs an explanation. Flags and `--check` use the selected basis
only, and each city's provenance line states `clean_cities_basis=<value>`.

Explained-against marker: the Explanations section carries one HTML comment of the form
`explained-against: berlin=11 paris=12 ...` (city=run id, set between the comment delimiters),
naming the run each city's explanations were written against. When a city's latest run (of the config on disk) is another run, `--check`
exits 1 and prints the corrected marker line; after re-checking the explanations against the
new run, paste that line over the old one. `--check` also exits 1, naming the city, when a city
has no done run of the current config.

<!-- explained-against: berlin=147 copenhagen=150 paris=148 vienna=149 wroclaw=151 -->

Evidence used below: tier and road km from the run rows (`velometer.sqlite`, runs 147–151, OSM
2026-09-30, classifier v2, GISCO LAU 2024). These explanations were first written against the
v1 runs 11–15 on the same snapshot. Against those, the v2 runs have identical road km and
identical tier A–E km in every city except Berlin, where the `,` value separator adds 0.08 km
to tier A per side (A+B 1,557.87 -> 1,557.96 km; centreline 918.34 -> 918.39 km); v2's other
additions (`use_sidepath`, `shoulder`, `crossing`, untyped `yes`) are excluded and move only
excluded and unrecognised km. On the Paris and Wrocław snapshots, v1 and v2 give every
road side and way the same tier A–E (compared side by side on 2026-10-02), so the way-level
analyses in `paris/qecio_shared_km` and `wroclaw/bnk_network_km`, first made with v1, hold
for v2. Further evidence: the external rows and their notes, the QECIO v2.10
Methodology PDF (Table 2) and `docs/research/m2-data-sources-2026-10-01.md`. "Centreline" means
our `qecio_weighted` basis: a bidirectional way counts once and each one-way side counts half,
which is how QECIO counts and, judging by Berlin and Wrocław, how the ECF tracker numbers in
Clean Cities count. Our `cc_km` and the `clean_cities_2025` preset use the `per_side` basis, in
which every side counts in full. The Clean Cities figures are dated 2025-05-14, 504 days before
our snapshot; QECIO is dated 2024-01-10/11, 994 days before it.
